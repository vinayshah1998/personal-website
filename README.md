## Getting Started

First, run the development server:

```bash

# or
yarn dev
# or
pnpm dev
# or
```

## Build and test

Node.js 20 or newer is needed for the local tooling.

| Command | What it does |
| --- | --- |
| `npm run build` | Production build. The `/stats` page fetches Strava data at build time, so `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET` and `STRAVA_REFRESH_TOKEN` must be set or the build fails with "Missing Strava API credentials". |
| `npm run lint` | ESLint over the repository. |
| `npm run typecheck` | `tsc --noEmit`. |
| `npm test` | Unit tests for the island game logic (`tests/unit`), run with Node's test runner through `tsx`. |
| `npm run test:e2e` | Playwright tests (`tests/e2e`) on desktop Chrome and Pixel 7 with SwiftShader WebGL. |

`npm run test:e2e` runs `npm run build` and then starts a fresh `next start` on `127.0.0.1:3217` (override with `ISLAND_PORT`). It never reuses a server that is already running and fails if the port is taken. The build needs the Strava variables. For local verification without real credentials, pass placeholders on the command line only; the build then logs a failed Strava token refresh and `/stats` is built without Strava data:

```bash
STRAVA_CLIENT_ID=placeholder STRAVA_CLIENT_SECRET=placeholder STRAVA_REFRESH_TOKEN=placeholder npm run test:e2e
```

To smoke-test a deployment instead, set `ISLAND_BASE_URL`. No local build or server is started:

```bash
ISLAND_BASE_URL=https://vinayshah.dev npm run test:e2e
```

Screenshots go to `.audit/screens` (override with `ISLAND_SHOTS`). Install the browser once with `npx playwright install chromium`.

## Island assets (Blender)

The home page island and penguin are generated by a script, not modelled by hand.

- Generator: `assets/blender/generate_island.py` (seeded, `random.Random(20260929)`)
- Outputs: `public/island/world.glb`, `public/island/penguin.glb` and the source scene `assets/blender/island.blend`
- Blender backup files (`*.blend1`) are ignored and should not be committed

The committed assets were produced with Blender 4.3.2 from the Debian package `blender 4.3.2+dfsg-2` (arm64), with `python3-numpy 1:2.2.4+ds-1` for the glTF exporter. That ran in a `public.ecr.aws/debian/debian:trixie` container on an arm64 host, because blender.org publishes no Linux arm64 build. Upstream blender.org binaries were not used.

To regenerate with any Blender 4.x on your `PATH`:

```bash
npm run assets:island
# which runs:
blender -b --factory-startup --python-exit-code 1 --python assets/blender/generate_island.py -- .
```

The same environment as the committed assets, in a container (install once, then run as your user so the outputs are not root-owned):

```bash
docker run --name island-blender-setup public.ecr.aws/debian/debian:trixie bash -c \
  "apt-get update && apt-get install -y --no-install-recommends blender python3-numpy"
docker commit island-blender-setup island-blender:local && docker rm island-blender-setup
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD":/work island-blender:local \
  blender -b --factory-startup --python-exit-code 1 --python /work/assets/blender/generate_island.py -- /work
```

Debian may ship a newer `blender` point release than 4.3.2 over time; check with `blender --version` inside the image.

Regeneration gives equivalent assets: the same named objects, layout and colours. It is not byte-for-byte identical across Blender or exporter versions, so expect GLB and `.blend` diffs after a rerun even when nothing meaningful changed.
